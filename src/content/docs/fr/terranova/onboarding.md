---
title: Onboarding Terranova (bêta)
description: Étapes pour obtenir un accès Terranova et prendre en main les bases sans attendre la v1.
---

> Objectif : que chaque membre puisse naviguer dans Terranova, encoder une fiche projet simple et savoir où remonter ses questions.

## 1. Obtenir un accès
1. Vérifie avec Michael ou Bee si ton compte Google figure dans le groupe `terranova-beta`.
2. Si besoin, remplis la demande d’accès (formulaire interne) et joins le pôle auquel tu appartiens.
3. Tu recevras un e-mail d’invitation avec lien sécurisé (valable 24 h).

## 2. Première connexion
- Utilise ton compte Google Semisto (SSO).
- Choisis ton pôle principal (Design, Academy, Nursery, Roots) → cela active les bons modules.
- Configure ton profil : photo, rôle, numéro de téléphone (utile pour les alertes terrain).

## 3. Parcours express (15 minutes)
| Étape | Action | Durée |
| --- | --- | --- |
| Tableau de bord | Repérer les widgets clés (projets actifs, tâches du jour). | 3 min |
| Module Design | Ouvrir un dossier client, vérifier les étapes OBREDIM. | 4 min |
| Module Academy | Consulter un événement de formation, télécharger la feuille de présence. | 4 min |
| Module Nursery (aperçu) | Lire la fiche “Stocks” (même si lecture seule). | 2 min |
| Feedback | Noter ce qui manque / ce qui est confus. | 2 min |

## 4. Premier enregistrement
1. Crée (ou mets à jour) une fiche “Contact” ou “Projet” de ton pôle.
2. Ajoute une note interne + un document (ex. devis, plan, photo).
3. Tagge la fiche avec `beta-feedback` si tu remarques un bug ou une friction.

## 5. Support & feedback
- **Questions rapides** : canal Slack `#terranova-beta` (Bee + équipe Super Génial).
- **Bugs bloquants** : formulaire “Incident Terranova” (lien dans le canal).
- **Idées d’amélioration** : ouvre une carte dans Trello “Terranova backlog” ou écris directement à Bee.

## Ce qui n’est pas encore prêt
- Automatisation Nursery (inventaires + étiquettes) → prévu pour la v1.
- Suivi Roots / bénévoles → migration en cours.
- Export comptable → nécessite encore les gabarits d’Eddy.

## Bonnes pratiques
- Encode les infos dès qu’une action est faite, même pendant la bêta (ça aide à tester la performance).
- Documente *toutes* les anomalies avec captures d’écran.
- Reste bienveillant·e : l’objectif est de rendre Terranova utile pour toute l’équipe avant l’été.
